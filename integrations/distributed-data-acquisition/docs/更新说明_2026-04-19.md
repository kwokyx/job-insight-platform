# 更新说明（2026-04-19）

本次更新完成了“采集结果入 HDFS”第一阶段能力，实现目标是在保留原有分布式采集架构的前提下，将职位原始明细按固定字段范围同步写入 HDFS，供后续 Hive/Spark 分析使用。

## 本次更新内容

### 1. 新增 HDFS 双写能力

- 在调度中心新增 HDFS 配置项
- 在 `DataConsumer` 中接入 HDFS 批量写入线程
- 采集结果在写入 MySQL `job_data` 后，同时写入 HDFS JSONL

### 2. 固定 HDFS 存储路径

当前职位原始明细写入：

```text
/data/recruitment_crawler/ods/job_detail/channel=zhaopin/dt=<YYYY-MM-DD>/
```

### 3. 固定 HDFS 字段范围

进入 HDFS 的字段固定为 21 个：

- `url`
- `url_obj_id`
- `title`
- `salary_min`
- `salary_max`
- `salary_raw`
- `job_city`
- `experience_year`
- `education_need`
- `publish_date`
- `job_welfare`
- `job_labels`
- `position_info`
- `job_classification`
- `company_name`
- `company_size`
- `company_finance`
- `crawl_time`
- `crawl_update_time`
- `company_logo`
- `task_id`

### 4. 解决 WebHDFS 第二跳重定向问题

由于调度中心运行在 Windows 环境，NameNode 返回的 DataNode 重定向地址使用 `hadoop001/002/003` 主机名，Windows 默认无法解析。  
本次增加 `HDFS_REDIRECT_HOST_MAP`，会自动将重定向地址改写为 IP 后上传：

```text
hadoop001=192.168.152.151
hadoop002=192.168.152.152
hadoop003=192.168.152.153
```
